# torrcast

> **日本語について。** 本製品は日本語に対応していません。画面表示、メッセージ、音声トラックの
> 自動選択は英語とロシア語のみです。ワンライナーでのインストールは**英語版**が入ります。
> このページはドキュメントの翻訳です。

`cast` は、映画、ドラマ、アニメを名前で探してテレビに映すコマンドラインツールです。データの
経路にクラウドはなく、トレントを一つずつクリックして回る必要もありません。映像はピア群
（スウォーム）から手元のパソコンへ、そこからテレビが見ている経路を通ってテレビへ流れます。
間に第三者のサーバーは入りません。

映画がディスクに置かれるのは視聴している間だけです。再生中、torrcast は映画の全体を背後で
ダウンロードし、必要なところは変換します。先読みキャッシュが済めば、残りはインターネット
なしで再生でき、シークもバッファリングなしで動きます。キャッシュは再生後に削除されます。
メディアライブラリもダウンロード待ち行列もありません。ディスクにあるのは今再生しているもの
だけで、しかも再生している間だけです。

考え方は単純です。**頼めば再生が始まる**。コマンド一つ、質問一つ、多くの場合は質問すらなく、
そして画面に映像が出ます。リリースを選ぶ手間も、ダウンロード待ち行列も、音声トラックの
やりくりもありません。

二つ目の原則は、**最高の鮮明さよりも途切れない再生**です。再生はバッファリングしてはなり
ません。リリースが受信機にとって重すぎる場合、torrcast はその場で変換し、そのことを伝えます。
画質を落とすのは最後の手段としてだけ、しかも必要な分だけです。

黙って差し替えることはありません。自動で下した判断はすべて、正直な一行になります。たとえば
`release 1 actually 574p - taking 2 (actually 1080p)`、`attention: ~36 Mbit/s - heavy chunks
get recoded on the fly`、`video hevc - recoding it whole on the fly` のように。

## インストール

```sh
curl -fsSL https://torrcast.anysda.space | sh
```

素の Debian 12 には `curl` が**入っていません**。先に入れてください。ブートストラップには
`curl`、`tar`、`sha256sum`、`bash` が必要です。ワンライナーは GitLab に最新版を問い合わせ、
そのリリースの tarball をダウンロードし、SHA-256 チェックサムを検証し、中の `install.sh` を
実行します。root 以外で実行された場合、ブートストラップは `sudo` 経由で自分を起動し直します。
`sudo` がない環境では処理を止め、root で実行すべきコマンドをそのまま表示します。

エンドポイントは、そこから入る製品の言語を表しています。`https://torrcast.anysda.space` は
英語の `cast` を入れます。メニュー、メッセージ、探しに行く音声トラックがすべて英語です。
`https://rutorrcast.anysda.space` は同じリリースを、製品の言語をロシア語にして入れます。
どちらにしても選択は最終的なものではありません。`cast --en` と `cast --ru` で、入れた本体を
いつでも切り替えられます。

ソースから入れる場合:

```sh
git clone https://gitlab.anysda.space/anysda/torrcast && cd torrcast
sudo ./install.sh
```

`sudo ./install.sh -en` と `sudo ./install.sh -ru` は言語を手で指定します。このキーは
インストーラー自身の出力と、設定の `language` フィールドの両方を決めます。キーを付けない
場合、新規インストールでは英語が保存され、再インストールでは設定にすでにある言語がそのまま
保たれます。

インストールは mDNS と、ローカルサブネットのポート 8009 の走査で受信機を見つけます。一台
だけなら自動的に保存されます。複数見つかった場合、インストーラーは名前とアドレスを並べ、
選ばずに先へ進みます。アドレスを直接保存するには `cast --tv <ip>`、番号で選ぶには `cast --tv`
を使います。

インストーラーの最後の画面は受信機そのものについて語ります。保存された受信機は名前と
アドレスで示され、機器が名前を名乗らなかった場合や、設定にアドレスしか入っていない再
インストールの場合はアドレスだけで示されます。複数見つかったときは、コマンド一覧の下に
収まるだけ並べ、残りを数えます。「and 2 more」のように。何も見つからなくても黙っては
いません。画面はテレビを点けるよう促し、`cast --tv` を名指しします。端末が狭ければ文面は
縮みますが、コマンドがそこから落ちることはありません。模擬の試験台はそれと分かるように
示されます。どこにも映さないからです。同じ画面が、もう一方の言語への扉も名指しします。
英語でインストールしたなら `cast --ru` です。

`install.sh` は冪等です。もう一度実行しても、変わったところだけが更新されます。登録も外部の
API キーも要りません。Prowlarr は自分の API キーを生成し、インストールはそれを読み出して
torrcast の設定に保存します。設定されるインデクサーはアカウントも captcha もキーも必要と
しません。Knaben、RuTor、Nyaa.si、YTS には直接つなぎ、torrcast と一緒に入って localhost だけ
で待ち受ける二つの小さなローカルの読み取り専用アダプターが、AniLibria（ロシア語音声の
アニメ）と JacRed（ロシア語のリリースと音声の公開カタログ）を加えます。プロバイダーが
インデクサーを名前で遮断している場合、インストールはローカルの迂回路を用意し、その名前が
それ越しに応答するかどうかを伝えます。

TorrServer と Prowlarr は、システムの他の部分と組み合わせて試験済みのバージョンに固定されて
います。どちらの固定値も `install.sh` の先頭の設定ブロックにあります。固定した Prowlarr の
リリースが GitHub から消えている場合、インストールはそう告げて最新版を代わりに取ります。
TorrServer が差し替えられることは決してありません。固定したビルドが見つからないとき、すでに
入っているバイナリはそのまま残され、インストールはそう告げます。バイナリのない機械では、
インストールは停止します。

パッケージの工程は検査で終わります。スクリプトはインストールされたパッケージのファイルを
一つ残らず `install.sh` の隣にあるソースと比較し、`venv vs repository check: N files match
(sha256 ...)` のような行を表示します。食い違いがあれば、異なるファイルを名指しし、成功を
報告せずに失敗します。

パッケージは `/opt/torrcast/venv` に置かれ、`/usr/local/bin/cast` は
`/opt/torrcast/venv/bin/cast` へのシンボリックリンクです。

## 要件

- systemd を備えた Linux。Debian 12 以降、または Python 3.11 以降がシステムのパッケージ
  マネージャーから手に入る Ubuntu。インストールは `apt` を使います。
- Python 3.11 以降。`install.sh` は `python3.13`、`python3.12`、`python3.11` のうち最も新しい
  ものを取ります。`TORRCAST_PYTHON` でインタープリターを手で指定できます。
- `ffmpeg` 6.1 以降。`-readrate_initial_burst` が必要だからです。システムのものが古い場合、
  snap に閉じ込められている場合、MPEG-TS の煙試験に落ちる場合は、`install.sh` が静的ビルドを
  `/usr/local/bin` に置きます。
- systemd ユニット、パッケージ、`/opt`、`/etc`、`/var/lib` 以下のディレクトリを入れるための
  root 権限。
- メモリ。測定は 8 GiB の機械で取っています。それより小さい機械でも、キャッシュを小さくすれば
  動きます。ライブの HLS セグメント窓は `/dev/shm` に、二つの ffmpeg プロセスと並んで置かれる
  ので、トレントのキャッシュをメモリに置く場合、インストールはシステムとプレーヤーとその
  プロセスのために 1.75 GiB を差し引いてから大きさを決めます。このキャッシュこそがインター
  ネット断から再生を守るもので、より多く入る場所に置かれます。通常はディスク上、RAM に余裕が
  あってディスクが窮屈な機械ではメモリ上です。大きさは機械から計算され、256 MiB から 8 GiB の
  間に収まります。`TORRCAST_TS_CACHE`（バイト）と `TORRCAST_TS_CACHE_DIR` で大きさと場所を
  上書きできます。
- 空きディスク約 33 GB。先読みキャッシュ用に 30 GB（`/var/lib/torrcast/warm`、設定の
  `warm_dir` と `warm_budget_gb`）と、決して手を付けないパーティション上の 3 GiB です。
  ディスクに余裕があれば、インストールはそこに最大 8 GiB のトレントキャッシュも置きます。
  なければキャッシュを縮めるか、メモリへ移します。先読みの予算はすべての作品で共有され、
  新しい作品が入ると、最も長く触られていないものが追い出されます。空きが足りなくなると、
  先読みは明示的な一行を出して止まります。`disk budget of 30 GB is used up`、あるいは
  `the partition has N GB free - that's the last reserve` です。その間も再生はライブ窓から
  続きます。
- 同じネットワーク上にある、**Chromecast** 受信機を内蔵したテレビまたはセットトップボックス。

> **受信機について。** 実測して同梱しているプロファイルは二つ、`cautious (Samsung Q70D)` と
> `Android TV box (Xiaomi TV Stick)` です。torrcast は受信機の身元情報を読んでどちらかを
> 選びます。認識できない受信機には慎重な方のプロファイルが割り当てられます。そうした受信機も
> 動くことはありますが、保証はありません。

## コマンド

```text
cast <query> [sNeM] [--voice [N|STUDIO]] [--new] [--dry] [--pick N] [--menu] [--release N] [--file N]
cast                    # same as cast status
cast stop               # stop casting and save the position
cast status             # what plays, position/duration, file, track, stream, warmed share
cast doctor             # check terminal, locale, ffmpeg, services, receiver, and stream
cast log [--since WHEN] # sessions since 2d / 12h / 30m / YYYY-MM-DD
cast --tv               # find receivers; take a single one, or choose by number
cast --tv <ip>          # save an address directly
cast --en               # the whole product in English: text, bot replies and voice tracks
cast --ru               # the whole product in Russian
cast -tg                # open Telegram bot setup
cast -h, --help         # help with every public option
cast --version          # version
```

`sNeM` はシーズン N、エピソード M を意味します。たとえば `s2e5` です。これはオプションでは
なく、位置指定のクエリの一部です。`2x5` も同じ要求の書き方として受け付けます。

うまくいく道筋では、torrcast に確信があるかぎり何も尋ねません。工程の行はライブの端末では
同じ場所に描き直され、かかった時間を添えて閉じられます。以下の実行例は省略してあります。
リリース番号、所要時間、シード数はインデクサーとピア群の答え次第で変わるからです。

```text
$ cast matrix
searching “matrix”... 2.4 s
taking “The Matrix (1999)” - 3 pictures matched; another one: cast releases matrix and --pick N
...
packing... 3.1 s
waiting for the TV... 1.2 s
playing “The Matrix” (1999) · 1080p · eng - on TV   (start 9 s)
```

検索のあと、コマンドは選んだ作品を名指しし、そのままリリースの選択へ進みます。`--menu` は
作品を明示的に尋ねます。正直な既定値がないときは、メニューが自分から現れることもあります。
たとえば、求められたシリーズの該当作が結果になく、どれを選んでも別の映画を再生することに
なる場合です。

```text
$ cast matrix --menu
searching “matrix”... 2.4 s
  1. The Matrix (1999) · IMDb 8.7 · 2 h 16 min
     The Matrix is a 1999 science fiction action film written and directed by the
     Wachowskis.
  2. The Matrix Reloaded (2003) · IMDb 7.2 · 2 h 18 min
     ...
  3. The Matrix Revolutions (2003) · IMDb 6.7 · 2 h 9 min
     ...
Enter - “The Matrix (1999)”, item 1 of 3
What are we watching? [1]:
```

一覧は年代順で、角括弧の中の数字が Enter で選ばれるものです。すなわち、**自分のピア群が
生きているシリーズ最初の作品**です。シリーズは頭から観るもので、ピア群が死んでいる作品は
飛ばされます。質問のすぐ上の行が、その既定値を名前で言い切ります。既定値が一行目でないことは
よくあるからです。

評価、上映時間、一文の説明は、公開されていてキーの要らない情報源から背後で届きます。
Wikipedia、Wikidata、そして `install.sh` がディスクに置く IMDb の評価エクスポートです。
メニューは説明を待ちます。説明は数行を占めるので、誰かがすでに読んでいる項目の下に押し込む
わけにはいかないからです。評価と上映時間は待ちません。これらは表示済みの行にその場で
書き込まれ、カーソルの下で行が変わります。この待ち時間は上限であって遅延ではありません。
1.5 秒、説明のために二度目の問い合わせの波が要る英語では 2.7 秒で、説明が揃った瞬間に、
あるいは言うことが何もなければ直ちにメニューが現れます。

名前が同じで年が違う作品は、別々の作品として扱われます。最も活気のあるものが選ばれます。
ピア群の活発さこそ、何を指していたかの最良の推測だからです。これが黙って行われることは
ありません。行はその作品を年つきで名指しし、その最良のリリースのシード数、同じ名前に該当する
他の作品の数、そしてそれらを列挙する `--menu` コマンドを示します。ですから `cast mummy` は
最も活気のある「Mummy」を選んでそう告げ、`cast mummy --menu` は尋ねます。クエリの中の数字は
シリーズの何作目として、ドラマの場合はシーズン番号として読まれます。

正直な既定値がない場合、メニューには答えなければなりません。Enter は何も選ばず、数字が
与えられるまで質問が繰り返されます。`cast matrix --pick 2` は項目を先に名指しし、何も
尋ねません。番号は表示された並びと照合されるので、今は別の作品を指す番号は、黙って再生される
のではなく名前を挙げて拒まれます。端末がない場合、pty のない SSH 越しや cron からの実行では、
質問は声に出して拒まれ、その拒否は逃げ道を両方とも名指しします。正確な題名か、`--pick N`
です。

再生行の `start N s` は、**画面に最初のライブフレームが出るまで**の時間であって、
パッケージングを始めた時刻までの時間ではありません。受信機は映像を映すより早く `PLAYING` を
報告するので、その数字はお世辞になってしまいます。

観終わっていない作品は、同じリリース、同じファイル、同じトラックで、保存された位置から
黙って再開されます。再生行がそのことを告げ、そこから抜ける方法で終わります。

```text
playing “Cyberpunk” · s1e2 · 1080p · track 1 · from 0:03:20 · pick another: --menu - on TV   (start 6 s)
```

`--new` は同じリリース、ファイル、トラックを最初から再生します。`--menu`、`--pick N`、
`--release N`、`--file N` はそれぞれ自前の作品やリリースを尋ねるもので、しおりで答えられる
ことはありません。エピソードを明示するのは別の要求です。保存されたリリースの中で位置を
飛びます。

### シリーズ作品

エピソードはクエリの中で指定します。`cast <series> s2e5` あるいは `cast <series> 2x5` です。
エピソードのメニューはありません。`cast <series>` は記録されたトレントの次のエピソードを
再生し、`cast stop` のあとは保存された位置から再開します。

エピソードは自分で続きます。同じトレントの次のファイルが、質問もなく、受信機への接続を
やり直すこともなく始まります。受信機側のアプリケーションはエピソードの間も立ち上がった
ままで、作品が終わったときにだけ閉じられます。再生ユニットは次に来るものを名指しします。
`next episode: s2e6` です。

シーズンが尽きても作品の終わりではありません。ユニットは自分で次のシーズンを探します。同じ
題名と次のシーズンの第1話を要求し、そこから再生します。

```text
«Doctor Who» - season 2 watched, searching season 3
```

次のシーズンがない場合、その理由が声に出して告げられ（`«Doctor Who» - season 2 was the
last: ...`）、再生は終わります。使い切ったトレントに対してあとから `cast <series>` を実行
すると、最初から始めてそう告げます。`“Doctor Who” - s2e13 was the last one in the release,
so playing from the start` です。

### 音声トラック

リリースの選択は自動で、却下は一つ残らず名指しされます。

```text
release 2 does not fit (av1) - taking 5
```

HEVC をデコードできない受信機には、ストリーム全体の変換が行われます。HEVC と名の付いた
リリースが待ち行列に入るのは最後の望みとしてだけで、求められたエピソードを載せた普通の
リリースが一つも生きていない場合に限られます。全体変換は最初の一秒からエンドロールまで CPU を
占有し、開始も数秒遅くなるからです。2160p のリリースも同じように、1080p へ縮小する全体変換を
通して再生されます。1080p がないときに選ばれ、生きている 1080p を上回ることは決してありま
せん。ビットレートの上限より重いリリースは、そもそも待ち行列に届きません。シードがゼロの
リリースは生きている隣人より下に沈み、選ばれたリリースのピア群が黙ったままなら、選択は最初の
リリースで諦めるのではなく、自分の予算の中で待ち行列を下へ進みます。

音声トラックの選択も自動で、製品の言語に従います。英語でインストールした場合、英語の音声が
先頭に来て、次に作品自身の原語、その次にロシア語が並びます。音声解説と制作陣のコメンタリーは
最下位に置かれます。同じ階層の中では素直なトラックが勝ちます。吹き替えより原語が上、ロシア語
のトラックの中では吹き替えが多人数吹き替え、二人吹き替え、一人吹き替えより上です。
`cast --ru` は代わりにロシア語の序列を上に置きます。再生行は選ばれた音声トラックを名指し
します。

同じ要求はリリースの選択にも及びます。英語のもとでは、音声の身元情報に英語トラックが確認
できないリリースは飛ばされ、待ち行列は先へ進みます。調べたリリースのどれにも英語がなかった
場合、torrcast はその中で最良のものを再生し、そう告げます。

```text
no English voice in any of the checked releases (4) - turning on release 2, sound Japanese
```

明示的に指定した音声トラックはその作品について記憶され、あとから `cast` を実行すると
再利用されます。自動選択がこの記憶に書き込むことはありません。記憶した音声が新しいリリースに
ない場合、torrcast は `no “eng · Original” voice track in this release - taking the usual
one` と告げ、記憶はそのまま保ちます。

```text
cast voices <query>             # voice tracks of the release that would play
cast <query> --voice N          # take track N and remember it
cast <query> --voice STUDIO     # take a track by studio name or label, and remember it
cast <query> --voice            # numbered menu of tracks
```

`cast voices` は選ばれるはずのリリースと、その番号つきトラックを表示し、自動選択の
`[default]` と `[remembered]` に印を付けます。`--voice` に渡した名前は、大文字小文字と空白を
無視して全体として照合され、部分文字列としては照合されません。`MVO` は `MVO (LostFilm)` に
一致しません。

### セッションログ

torrcast は、テレビを消したあとで調べられるよう、自前の再生記録を残します。

```text
cast log                 # the last three sessions
cast log --since 2d      # everything since a boundary (2d / 12h / 30m / YYYY-MM-DD)
```

`--since` なしでは直近三つのセッションが表示されます。付けると境界が過去へ動き、セッション数
の上限はなくなります。一つのセッションは一本の映画、または一話のエピソードです。エピソードは
それぞれ自分の項目を開き、`cast` 一回分の検索とリリース選択は、それらの項目が延長していく親の
識別子の下に並びます。こうして一回の実行が散らばることはありません。

セッションには、クエリと、それが持ち帰った行数と作品数、インデクサーごとの結果件数と所要時間
または沈黙、候補が落とされた理由つきの待ち行列、選ばれたリリースとその画質、トラック、
ビットレート、あらゆる再バッファリング、ネットワーク断、停止、受信機の脱落、エラー、そして
最後まで観たのか、ある位置で止めたのかが記録されます。どの行にもセッション開始からの経過が
付きます。

記録は状態ファイルの隣に、一日一本の JSONL として保存され、七日間保持し、合計 64 MiB を
上限として古いものから消されます。どこにもアップロードされません。書き込みは容量の決まった
背後の待ち行列を通るので、再生がディスクを待つことはありません。その待ち行列が溢れたときは、
落ちたレコードの数が記録そのものに入るので、欠落が黙って起きることはありません。一週間何も
再生していない場合、`cast log` は `no trace - not a single session over the week` と表示
します。

### デバッグ用の操作

これらの操作は、明示的に求めたときにだけ内部を見せます。

```text
cast releases <query>              # table of releases per picture, then exit
cast <query> --release N           # use release N; numbers come from cast releases
cast <query> --release N --file N  # also take file N of that release
cast <query> --dry                 # the whole resolve without casting
cast <query> --new                 # the same release, file and track from the start
cast <query> --menu                # list the pictures and ask, instead of choosing
```

手で指定したリリースやファイルが差し替えられることは決してありません。選択の関門はそれを
裁かず、待ち行列には他に何も入りません。一時停止とシークはテレビのリモコンで行います。終了
コードは、成功が `0`、何も見つからなかった場合が `1`、torrcast が回避できなかった障害
（サービスまたは受信機）が `2`、人が質問を取り消した場合が `3` です。`cast doctor` は検査の
いずれかが落ちると `2` を返します。

## 仕組み

```text
query -> search (Prowlarr) -> parse (torrent names, franchises, sNeM)
      -> stream (TorrServer) -> ffmpeg -> HLS -> cast (Chromecast)
                            \-> warm (whole movie to disk, background)
```

常駐する再生デーモンはありません。作品ごとに `cast` が一時的な `torrcast-play` ユニットを
起動し、そのユニットが ffmpeg、HLS サーバー、位置の見張りを抱えます。配信アドレスはテレビ
への経路から導かれるので、受信機には実際に見えているインターフェイスの生の IP が渡され、再生
の経路に DNS が入ることはありません。再生が続いたままコマンドだけが終了することもあります。
ユニットのログは `journalctl -u torrcast-play` で、`cast stop` はユニットを止め、ユニットは
落ちる途中で位置を書き出します。常駐するサービスは、TorrServer、Prowlarr、Prowlarr が
問い合わせるローカルの AniLibria と JacRed の検索アダプター、そして SNI 検査でホスト名が
生き残らないトラッカーのために、必要な名前だけを固定するローカルの TLS シムだけです。

先読みキャッシュは最初の映像を待ってから、`nice` のもとで実時間の4倍の速さで先を読みます。
行儀のよさだけではプロセッサは空かないので、ライブ再生の余裕が減ったときや、ライブの
エンコーダーが働いているときには、先読みは完全に凍結します（`SIGSTOP`）。今まさに観られて
いる場所が常に勝ちます。セグメントの格子は決定論的なので、セグメント `vN` はパッケージングを
どこから始めたかによらず映画の同じ場所を指し、先読み済みの断片とライブの断片は同じ名前の
もとで交換できます。先読み済みの範囲へのシークにネットワークは要りません。コピーするか変換
するかはキーフレームのマップから断片ごとに決められるので、重い断片だけが再エンコードされ、
コピーした断片と再エンコードした断片のつなぎ目はタイムスタンプでも音声でも連続したままです。

`cast status` は映画のどれだけが先読み済みかを報告し、全体が先読みできたときはそう告げます。
先読み済みの範囲より先で元が消えると、画面は暗くなり、torrcast はジャーナルと `cast status`
で、どれだけの間暗いのか、いつ諦めるのかとともにそのことを告げます。受信機自身の辛抱はそれ
より早く尽きるので、元が戻ったことを確認できしだい、torrcast は保存した秒数から再生を読み
込み直します。これを行うのは空いている受信機に対してだけで、他人の再生を中断することは
ありません。試行の回数は一回の断ごとに上限があり、それが尽きれば正直に暗いままとなり、次の
`cast` が保存された場所から再開します。

進行状況は `/var/lib/torrcast/state.json` にあり、原子的に書かれます。上映時間の95パーセント
の位置のしおりは、観終わったものとして数えられます。記憶される音声はトラック番号ではなく
トラックのラベルです。次の実行では別のリリースが選ばれ、そこでは同じ音声に違う番号が振られて
いるかもしれないからです。そのラベルが新しいリリースにない場合、torrcast は代わりに再生して
いる音声を名指しします。

設定は `/etc/torrcast/config.json` にあり、必須なのはテレビのアドレスだけです。ほかにあるのは
受信機と任意のプロファイルキー、Prowlarr と TorrServer の URL、Prowlarr の API キー、
トランスポート（既定は `http`。`https` も動きますが、テレビが信頼する証明書を求めます）、
配信アドレス、ポート、セグメントのディレクトリ、セグメントの格子とバッファの設定、
ビットレートと変換のしきい値、そして先読みの入り切り、ディレクトリ、ディスク予算、速度です。

受信機ごとに実測した性質がプロファイルを成します。セグメントの重さの上限、変換が必要な
コーデック、ビットレートのしきい値、受信機がセッションを切るまで待つ時間、停止のしきい値
です。機器自身の身元情報（メーカー、モデル、名前）がプロファイルを選びます。黙っている機器や
認識できない機器には慎重な方が割り当てられます。`cast doctor` は有効なプロファイルとその
出どころを名指しし、`cast log` は同じ行をセッションの要約すべてに載せます。
`receiver_profile` はプロファイルをキーで固定し、知らないキーは慎重な方に落ちます。設定に手で
書いたしきい値はプロファイルより優先されます。プロファイルが埋めるのは、慎重な方の既定値の
ままになっている値だけです。

## 開発

```sh
.venv/bin/ruff check
.venv/bin/ruff format --check
.venv/bin/mypy
.venv/bin/pytest
scripts/dead-code
```

五つすべてがコード 0 を返さなければなりません。`mypy` は引数なしで実行してください。その
対象範囲は `pyproject.toml` の `[tool.mypy] files`（`torrcast`、`tgbot`、`tests`、`scripts`）
が定めています。コマンドラインでパスを指定すると、その範囲が黙って狭まります。

`scripts/dead-code` は四つの段階を実行し、それぞれの対象範囲こそが要点です。呼ばれていない
名前は、パッケージと `scripts` をまとめて、しかし意図的にテストを除いて探します。そうすれば、
唯一の呼び出し元が自分の鏡テストであるようなコードは、そのテストごと取り除かれます。第二段階
はどのテストからも呼ばれない名前を、第三段階は誰も import しないパッケージのモジュールを、
第四段階はどのテストも要求しないフィクスチャを探します。import のグラフでは見えない呼び出し元
は明示的に名指しされています。`scripts/vulture-whitelist.py` にある `http.server` の
リクエストハンドラー、そしてグラフの起点としては、コンソールのエントリーポイント、
`python -m`、`scripts/` の中の測定器、インストーラーとインデクサー定義が文字列として挙げて
いる名前です。

`scripts/test-gate` はそのすべてに加えて、構造の関門、CLI とインストーラーの契約、配線の鏡、
機械と ffmpeg の試験一式を実行します。

レイヤーは `domain`（純粋なモデルと規則）、`ports`（外部との契約）、`usecases`（シナリオ）、
`adapters`（ネットワーク、ディスク、サブプロセスに触れてよい唯一の場所）、`cli`、`runtime`
（配線）です。パッケージのレイヤーのうち `adapters` を import してよいのは `runtime` だけ
です。`scripts/structure-gate` は16の規則を強制します。その中には、1モジュールにつき公開の
クラスまたは関数は一つ、モジュール名はそれに合わせる、200行の上限、すべてのモジュールに鏡
テスト、そしてその import 表があります。どの規則にも `tests/test_structure_gate.py` に否定の
検査があります。`scripts/where.py` はシンボルがどこで宣言されているかを教えます。

`scripts/` ディレクトリには、セグメントの格子とキーフレームのマップ、コールドスタートと変換の
ベンチマーク、トレントのトラッカー検査、音声トラックの収集、実機の受信機での煙試験のための
測定器も入っています。測定器は入力のパスをコマンドラインで受け取り、出力を書くときにはその
隣に `<output>.passport.json` を落とします。中身は、コミット、パッケージのファイル自体から
計算した指紋、測定器自身の名前と SHA-256、時刻、コマンドライン、そしてすべての入力と出力の
大きさ、行数、SHA-256 です。コミットは欠けることがあります。コードはリポジトリのない機械にも
複写されるからです。指紋が欠けることはなく、二回の実行が同じコードを使ったことを証明するのは
これです。

このパスポートは、実行そのものが有効だったかどうかも述べ、それを誰も測っていない場合には
そう明示します。沈黙は「有効」と読まれてしまうからです。実機の受信機での測定は二つの計器、
torrcast 自身の記録と受信機自身のログで取られ、二つ目は黙って止まることがあります。受信機の
ログが見えなくなった実行は、損なわれた測定として報告され、その停止回数はそもそも表示され
ません。死んだ計器が稼いだゼロを通すよりはましだからです。付き添いの見張りである
`scripts/probesign.py` は、ツリーの中のあらゆる受信機のしきい値が、それを測った測定器を
名指ししているかを検査します。
