# torrcast

**映画の名前を言えば、もうテレビで再生されている。**

> **日本語について。** 本製品は日本語に対応していません。画面表示、メッセージ、音声トラックの
> 自動選択は英語とロシア語のみです。ワンライナーでのインストールは**英語版**が入ります。
> このページはドキュメントの翻訳です。

ターミナルのコマンド一つで、映画、ドラマ、アニメを名前で探してテレビに映します。データの
経路にクラウドはなく、メディアライブラリもダウンロード待ち行列もなく、リリースや音声トラックを
手で選んで回ることもありません。映像はまっすぐ流れます。ピア群（スウォーム）から手元の
サーバーへ、そこからテレビへ。あなたと映像の間に第三者はいません。

## こう見えます

```console
$ cast matrix --menu
searching “matrix”... 2.4 s
  1. The Matrix (1999) · IMDb 8.7 · 2 h 16 min
     The Matrix is a 1999 science fiction action film written and directed by the
     Wachowskis.
  2. The Matrix Reloaded (2003) · IMDb 7.2 · 2 h 18 min
     ...
  3. The Matrix Revolutions (2003) · IMDb 6.7 · 2 h 9 min
     ...
Enter - “The Matrix (1999)”, item 1 of 3
What are we watching? [1]:
looking for an English voice: release 1 of 47 - tracks... 2.3 s
packing... 3.1 s
waiting for the TV... 1.2 s
playing “The Matrix” (1999) · 1080p · eng · Original - on TV   (start 9 s)
```

`--menu` を付けなければ質問は一切ありません。torrcast が最も生きている作品を選び、その名前を
一行で声に出して伝えます。`start 9 s` は画面に最初の映像が出るまでの時間であり、受信機が準備
完了を報告した時刻ではありません。あとはリモコンが主役です。一時停止もシークも、ほかの入力と
同じように効きます。この実行例は短くしてあります。リリース番号もシード数も所要時間も、
インデクサーとスウォームの答え次第で変わるからです。

## 便利な理由

- **コマンド一つ。** 頼めば再生が始まります。リリースを選ぶ手間も、ダウンロード待ち行列も、
  音声トラックのやりくりもありません。多くの場合、質問すら出ません。
- **ドラマは自分で進みます。** 次の話は質問なしに、テレビへ接続し直すこともなく始まります。
  シーズンが終われば torrcast が自分で次のシーズンを探し、その第1話から続けます。
  シリーズが終わったときは、そのことを正直に伝えます。
- **音声は自分で選ばれます。** 製品の言語に従います。英語版なら英語のトラックが先に、
  ロシア語版ならロシア語のトラックが先に来ます。`cast <query> --voice STUDIO` は、その作品の
  お気に入りの音声をずっと覚えます。
- **インターネットが切れても、映画は切れません。** 見ている間に、映画は背後でディスクへ丸ごと
  先読みされます。先読みが済めば、ネットワークなしで最後まで見られます。シークも含めてです。
- **ディスクに余計なものは残りません。** キャッシュは再生している間だけ存在します。
  メディアライブラリもなく、「そのうち掃除しないと」もありません。
- **数字より滑らかさ。** リリースが受信機に少し重ければ、重い部分だけをその場で変換します。
  画質を落とすのは最後で、しかもバッファリングを起こさないために必要な分だけです。
- **英語とロシア語を話します。** `cast --en` と `cast --ru` が製品全体を切り替えます。
  表示、メッセージ、ボットの返答、そして探しにいく音声トラックまで。
- **Telegram ボット。** `cast -tg` を実行すれば、チャットからテレビを操作できます。設定するとボットはサービスとして常駐するので、再起動後もチャットは応答します。
- **正直です。** 黙って差し替えることは一度もありません。自動で下した判断はすべて、
  分かりやすい一行になります。

```text
release 1 actually 574p - taking 2 (actually 1080p)
attention: ~36 Mbit/s - heavy chunks get recoded on the fly
video hevc - recoding it whole on the fly
```

## torrcast ではないもの

- **トレントのダウンローダーではありません。** ディスクにあるのは再生中のものだけで、しかも
  再生している間だけです。
- **メディアサーバーではありません。** ライブラリもウェブ画面もアカウントもありません。
  あるのはコマンドです。
- **クラウドサービスではありません。** 映像の経路に第三者のサーバーは入りません。テレビへ渡す
  アドレスはテレビまでの経路から求められ、再生経路に DNS は関与しません。

## インストール

```sh
curl -fsSL https://torrcast.anysda.space | sh
```

これは英語版です。ロシア語版は `https://rutorrcast.anysda.space` が入れます。どちらを選んでも
後戻りできます。`cast --en` と `cast --ru` が、入れたあとのコピーをいつでも切り替えます。
ワンライナーは GitHub に最新版を尋ね、そのバージョンの tarball を取得し、SHA-256 の
チェックサムを照合します。冪等なので、二度目の実行は変わったところだけを更新します。
登録も外部の API キーも要りません。

必要なもの: systemd の載った Linux（Debian 12 以降、または Ubuntu。インストールは `apt` を
使います）、Python 3.11 以降、インストールに root 権限、先読み用に約 33 GB の空きディスク、
そして同じネットワーク上にある **Chromecast** 受信機内蔵のテレビまたはセットトップボックス。
計測はメモリ 8 GiB の機械で行いました。少なければキャッシュが小さくなるだけです。

ソースから:

```sh
git clone https://github.com/anysda/torrcast && cd torrcast
./install.sh
```

フラグで言語を明示できます。`-en` は英語版、`-ru` はロシア語版です。フラグなしの新規
インストールは英語になります。root 権限はインストーラ自身が求めます。一般ユーザーで
実行すると `sudo` 経由で自分を起動し直しますし、すでに root の機械では `sudo` は
まったく要りません。

受信機はインストールが自分で見つけます。mDNS と、ローカルのサブネットを順に当たる方法です。
複数ある場合は `cast --tv` が一覧を出し、`cast --tv <ip>` がアドレスを直接書き込みます。

## コマンド

```text
cast <query> [sNeM]     # 探して再生する。sNeM はシーズンと話数: cast "doctor who" s2e5
cast                    # いま何が再生中か（cast status と同じ）
cast stop               # キャストを止め、位置を保存する
cast status             # 位置、ファイル、トラック、トレント、先読みの進み具合
cast doctor             # 端末、ffmpeg、サービス、受信機、トレントを点検する
cast log [--since 2d]   # セッションの記録: 再バッファも切断もすべて
cast voices <query>     # テレビへ送られるリリースの音声トラック
cast releases <query>   # 作品ごとのリリース一覧
cast -tg                # Telegram ボットの設定
cast --tv               # ネットワーク上の受信機を探す
cast --upgrade          # 最新リリースへ更新する（最新なら、そう伝える）
cast -h                 # すべてのフラグのヘルプ
```

便利なフラグ: `--menu`（どの作品かを尋ねる）、`--pick N`、`--release N`、
`--voice [N|STUDIO]`、`--new`（同じリリースを最初から）、`--dry`（キャストせずに解析だけ）。
途中まで見たものは黙って続きます。同じトレント、同じファイル、同じトラック、保存された位置
からです。再生の行がそのことを伝え、そこから抜ける方法も示します。

## 仕組み

```text
問い合わせ -> 検索 (Prowlarr) -> 解析 (リリース名、シリーズ、sNeM)
          -> ストリーム (TorrServer) -> ffmpeg -> HLS -> キャスト (Chromecast)
                                     \-> 先読み (映画を丸ごとディスクへ、背後で)
```

常駐の再生デーモンはありません。再生のたびに `cast` が一時的な systemd ユニットを立ち上げ、
その中で ffmpeg、HLS サーバー、位置の監視役が動きます。コマンドが終了しても再生は続きます。
先読みは `nice` の下で実時間の四倍の速さで先を読み、生きている再生が CPU を必要としたときは
完全に止まります。いま見られている場所が常に優先です。

受信機は実測のうえプロファイルとして用意してあります（Samsung Q70D、Xiaomi TV Stick の
Android TV ボックス）。知らない受信機には慎重なプロファイルが割り当てられます。デコーダーの
ない受信機での HEVC は丸ごと変換され、2160p は 1080p へ縮めて再生されます。そしてそのことは
必ず声に出して伝えられます。

コードは厳しい枠の中にあります。層構造（domain / ports / usecases / adapters / cli /
runtime）、コードより多いテスト、リンター、厳格な mypy、そして構造ゲート。どのリリースの前
にも、これらすべてが通っていなければなりません。
