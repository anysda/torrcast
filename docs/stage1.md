# Этап 1 — цепочка данных: что выяснилось на живых сервисах

Проверено на agent-ops (dev): Prowlarr 2.5.2.5491 и TorrServer MatriX.142.2,
оба на `127.0.0.1`, поставлены `install.sh`. Ниже — только то, что расходится
с ТЗ или закрывает открытые вопросы.

## Две правки к §8 ТЗ

**1. Эндпоинта `/api/v2.0/indexers/all/results` у Prowlarr нет** — это адрес
Jackett, Prowlarr на него отвечает 404. Агрегат по всем индексерам живёт на
`GET /api/v1/search?apikey=…&query=…&type=search&limit=100` и отдаёт JSON.
Torznab-XML у Prowlarr отдаётся по индексеру (`/<id>/api?t=search&q=…`), и мы
его тоже умеем разбирать (`search.from_torznab`) — это путь совместимости,
если индексер когда-нибудь подключат через Jackett.

**2. `magnetUrl` в выдаче — не magnet.** Prowlarr подставляет туда ссылку на
самого себя (`http://127.0.0.1:9696/1/download?apikey=…`), скачивающую `.torrent`
через прокси. Настоящая опора — поле `infoHash` (есть у 196 из 200 строк живой
выдачи). Magnet мы собираем сами: `magnet:?xt=urn:btih:<hash>&dn=<имя>&tr=…`
с зашитым списком открытых трекеров (`search.PUBLIC_TRACKERS`).

Категории при поиске: `2000` (кино) + `5000` (сериалы) + `8000` (Other).
Последняя обязательна — RuTor категорий не возвращает вовсе, и без `8000`
его выдача отсекается целиком (проверено: 191 результат против 91).

## Индексеры

| Индексер | Как заведён | Замечания |
|---|---|---|
| Knaben | `definitionName: Knaben`, `https://knaben.org/` | метапоиск: агрегирует RuTracker, TPB, Nyaa, 1337x; отдаёт `infoHash` |
| RuTor | `definitionName: rutor` (Cardigann), `https://rutor.info/` | категорий не отдаёт → маппится в `8000` |

Оба заводятся `install.sh` через `POST /api/v1/indexer`, ноль ручных шагов в
вебе. apikey Prowlarr генерит себе сам при первом старте — мы его вычитываем
из его же `config.xml` и кладём в `config.json` torrcast.

⚠️ Доступность мерена с agent-ops, у которого egress через VPN (NL). Для стенда
в LAN это НЕ показатель: RuTor там, вероятно, потребует zapret-контур (§10.1).
Knaben по разведке из LAN работает напрямую.

## 🔴 Пиры: DHT хватает

Открытый вопрос был: у RuTracker-раздач из Knaben нет публичных ретрекеров,
у RuTor-магнитов нет `tr=` вообще — вытянут ли пиры на одном DHT.
Замер (agent-ops, 05-08-2026, TorrServer MatriX.142.2, кэш в RAM):

| Плечо | Метаданные | Первые 256 КБ | Сидов / всего пиров (пик) |
|---|---|---|---|
| RuTracker (Knaben), только DHT | 5.0 с | 4.1 с | 3 / 198 |
| RuTracker (Knaben), DHT + наши `tr=` | 5.0 с | 7.7 с | 2 / 218 |
| RuTor, только DHT | 4.0 с | 1.9 с | 3 / 32 |
| RuTor, DHT + наши `tr=` | 3.0 с | 2.1 с | 3 / 26 |
| RuTor, DHT + `tr=` + ретрекеры TorrServer | 1.0 с | 1.4 с | 4 / 18 |

**Вывод: DHT самодостаточен.** Метаданные приходят за 1–5 с, первые килобайты
потока — за 1.4–7.7 с; это укладывается в бюджет §3.1 (DHT+метаданные 5–20 с)
с запасом. Открытые трекеры и `RetrackersMode=1` в TorrServer выигрыша по
времени не дают (разница в пределах шума), но остаются как страховка на
раздачах с редкими пирами — стоят они ничего.

Оговорка: замер сделан с agent-ops, у которого нет проброшенного порта, то есть
входящих соединений мы не принимаем — на стенде цифры могут быть только лучше.

## Мелочи, которые стоили отладки

* **Образы дисков.** Заметная часть русских раздач — DVD-Video (`VIDEO_TS`, 65
  файлов `.VOB`) или BDMV. Цельного файла внутри нет, стримить нечего. Такие
  раздачи из меню не убираем, но дефолтом они не становятся (`cli.is_disc`):
  иначе `cast тачки` по Enter упирался в «нет видеофайла».
* **Дефолт релиза** — самый обсиженный БЕЗ пометок ⚠ (не просто самый
  обсиженный): Enter обязан давать вариант, который ресивер точно съест.
* **Битрейт в меню** считается по размеру и типовой длительности (фильм 2 ч),
  потому что настоящую длительность даёт только ffprobe, а он работает уже
  после выбора релиза. После ffprobe цифра пересчитывается по факту.
* **Prowlarr надо настроить ДО первого старта**: иначе он садится на `0.0.0.0`
  и включает форму логина. `install.sh` пишет `config.xml` заранее —
  `BindAddress 127.0.0.1`, `AuthenticationMethod External`.
