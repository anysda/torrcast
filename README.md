# torrcast

Консольная утилита `cast`: находит фильм или сериал по названию (понимая франшизы
и кривые запросы), спрашивает **только про фильм** и стримит торрент на ТВ
через Chromecast — **без скачивания и без облака в пути данных**. Поток не покидает LAN.

Идейный наследник kinocast, но каталог — торрент-трекеры.

## Установка

Три действия, ноль регистраций и внешних API-ключей:

```sh
git clone git@192.168.1.25:anysda/torrcast.git && cd torrcast
./install.sh                      # зависимости, TorrServer, Prowlarr, юниты
cast --tv 192.168.100.102         # единственная настройка — адрес ТВ
```

Все внутренние ключи (Prowlarr↔cast) `install.sh` генерит сам.

## Команды

```
cast <запрос> [sNeM] [--new] [--voice N] [--dry]
cast stop      # снять каст, зафиксировать позицию
cast status    # что играет, позиция/длительность, источник
cast doctor    # самопроверка: терминал, локаль, Prowlarr, TorrServer, ТВ, раздача
```

Счастливый путь — один вопрос, и тот пропускается, когда картина единственная:

```
$ cast моана
поиск «моана»… 0.9 с
  1. Моана: романтика золотого века (1926)
  2. Моана (2016)
  3. Моана 2 (2024)
Что смотрим? [1]: 2
метаданные (DHT)… 4.0 с
дорожки… 4.7 с
упаковка… 0.5 с
жду телевизор… 8.6 с
играю «Моана» (2016) · 1080p · rus · Дубляж — на ТВ   (старт 19 с)
```

Релиз выбирается сам; не подошёл — строка «релиз №N не годится (hevc) — беру №2».
**Озвучка тоже выбирается сама** — «самая нормальная»: русский дубляж → русский
многоголосый → прочий русский → оригинал → чужой дубляж; тифлокомментарий и
комментарии съёмочной группы — в самый низ. Что взято, написано в строке запуска:
молчаливых подмен нет.
Сериалу список серий не показывается: `cast <сериал>` играет следующую невиденную.
«Старт NN с» означает **картинку на экране**, а не «упаковка пошла».

Выбрать озвучку руками можно флагом, и выбор **запоминается за этой картиной**:
`cast сопрано` в следующий раз играет ею же, ни о чём не спрашивая. Явный флаг
переписывает память; автовыбор её не трогает.

```
cast voices <запрос>              # какие озвучки есть у выбранного релиза
cast <запрос> --voice 3           # играть третью и запомнить
cast <запрос> --voice             # меню озвучек, как раньше
```

Посмотреть внутренности можно только явно — это отладочные ручки, не часть пути:

```
cast releases <запрос>            # старая таблица релизов, и выход
cast <запрос> --release N --file N
```

Пауза и перемотка — пультом ТВ. Коды выхода: `0` ок · `1` не нашли ·
`2` инфра-ошибка (Prowlarr / TorrServer / приёмник).

## Как устроено

```
запрос → search (Prowlarr/Torznab) → parse (имена раздач, франшизы, sNeM)
       → stream (TorrServer, кэш в RAM) → ffmpeg → HLS → cast (Chromecast)
```

Восемь модулей пакета `torrcast`: `cli` · `parse` · `search` · `stream` · `cast` ·
`state` · `console` (ввод и прогресс по фазам) · `doctor`. Полное ТЗ — [SPEC.md](SPEC.md)
и [SPEC-v2.md](SPEC-v2.md).

Постоянных демонов своих нет: на время показа `cast` поднимает transient-юнит
`torrcast-play` (ffmpeg + раздача HLS по http на голом IP + сторож позиции; адрес
берётся с той ноги, которой стенд смотрит на ТВ, так что DNS в пути показа нет).
Команда завершилась —
показ продолжается, логи в journald (`journalctl -u torrcast-play`), `cast stop`
гасит юнит и фиксирует позицию. Прогресс живёт в `/var/lib/torrcast/state.json`:
позиция ≥ 95 % длительности = досмотрено. Там же лежит память озвучки — подписью
дорожки (`voice`), а не номером: релиз в следующий раз может оказаться другим, а
«та самая» озвучка в нём — под другим номером. Нет её вовсе — об этом скажут вслух.

## Разработка

```sh
uv sync                 # venv на Python 3.12 + dev-зависимости
uv run ruff check .
uv run mypy
uv run pytest
```

> ⚠️ На agent-ops команда `cast` уже занята kinocast. Entry-point torrcast живёт
> только внутри venv проекта; системный алиас не трогаем.
